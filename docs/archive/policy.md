# NetSentinel 攻击类型防御策略

## 背景说明

NetSentinel 基于 eBPF/Hubble 在 L3/L4 层进行流量异常检测与响应。不同攻击类型在该层的可见性和可防御程度存在差异，需明确边界。

---

## 各攻击类型防御策略

### 1. DDoS-TCP SYN flood / DoS-TCP SYN flood

**L4 可见性：完整**

| 措施 | 说明 |
|------|------|
| SYN 包速率限制 | 同源 IP 每秒 SYN 包超阈值时限速或丢弃 |
| 源 IP 拉黑 | SYN 持续超阈值自动封禁源 IP |
| 启用 SYN cookie | 防止半连接队列耗尽，内核层防御 |

> L4 最能做的攻击类型，eBPF 可直接检测并下发 Cilium 策略阻断，闭环完整。

---

### 2. TCP sequence prediction

**L4 可见性：部分**

| 措施 | 说明 |
|------|------|
| 异常 TCP flag 检测 | 检测无 SYN 的 ACK、异常 RST 等非法 flag 组合 |
| 同源连接速率限制 | 限制同源 IP 每秒新建连接数 |

> L4 信号较弱，真正的防御依赖内核 TCP stack 的随机序列号机制，eBPF 层只能做辅助限速。

---

### 3. DoS Get

**L4 可见性：有限**

| 措施 | 说明 |
|------|------|
| 同源 IP 连接速率限制 | 限制每秒新建连接数 |
| 同目的端口并发连接限制 | 限制目标端口总并发连接数上限 |

> L4 不可见 HTTP 语义，无法识别 GET 请求内容，只能基于连接速率做通用限制。针对性防御应在 WAF/Ingress 层处理。

---

### 4. Slowloris

**L4 可见性：有限**

| 措施 | 说明 |
|------|------|
| TCP 连接建立超时 | Header 未在规定时间内完成则强制断开连接 |
| 同源并发连接数限制 | 限制同一源 IP 的并发连接数上限 |

> L4 可设置 TCP 连接超时，但无法判断 HTTP Header 是否完整。针对性防御需在 L7/Nginx 层配置 `client_header_timeout`。

---

### 5. Slow-body

**L4 可见性：有限**

| 措施 | 说明 |
|------|------|
| 低吞吐连接超时 | 连接长时间无有效数据传输则断开 |
| 同源并发连接数限制 | 限制同一源 IP 的并发连接数上限 |

> L4 无法感知应用层 body 传输进度，只能基于连接空闲时间做通用超时处理。

---

### 6. Slow-read

**L4 可见性：有限**

| 措施 | 说明 |
|------|------|
| TCP 接收窗口超时 | 接收窗口长期接近零时强制断开 |
| 同源并发连接数限制 | 限制同一源 IP 的并发连接数上限 |

> L4 可观察 TCP 窗口大小，但无法感知应用层读取行为。针对性防御需在 L7 层配置 `send_timeout`。

---

### 7. Slow-range

**L4 可见性：有限**

| 措施 | 说明 |
|------|------|
| 连接持续时间限制 | 超过最大连接持续时间强制断开 |
| 同源并发连接数限制 | 限制同一源 IP 的并发连接数上限 |

> L4 完全不可见 HTTP Range header，无法识别分片请求语义。只能依赖通用连接限制，针对性防御需在 WAF 层处理。

---

### 8. Bug in OpenSSL

**L4 可见性：无**

| 措施 | 说明 |
|------|------|
| 告警上报 | 检测到异常流量时触发告警，记录源/目的 IP |
| ⚠️ 无法在 L4 阻断 | TLS payload 加密不可见，L4 无法解析漏洞利用内容 |

> **L4 层对此类攻击无有效防御手段。** 根本解决方案是升级 OpenSSL 版本至无漏洞版本，或在应用层/IDS 层处理。eBPF 仅能做异常感知和告警。

---

### 9. Credentials Hijacking

**L4 可见性：极有限**

| 措施 | 说明 |
|------|------|
| 异常连接行为检测 | 检测非预期目标 IP/端口的凭据相关流量（如异常 LDAP、Kerberos、SMB 连接） |
| 同源异常外联限制 | 限制内部主机向外部未知 IP 发起的高权限端口连接 |
| 告警上报 | 检测到异常连接模式时触发告警，记录源/目的 IP 及端口 |
| ⚠️ 无法识别凭据内容 | TLS/加密流量下 L4 不可见凭据本身，无法判断是否被盗用 |

> **L4 层只能基于连接行为特征做辅助感知，无法直接识别凭据劫持行为。** 真正的防御需在身份认证层（MFA、证书绑定）、L7/零信任网关（mTLS、服务间认证）以及 SIEM/EDR 层处理。

---

## 总结

| 攻击类型 | L4 防御效果 | 补充防御层 |
|----------|------------|-----------|
| DDoS/DoS-TCP SYN flood | ✅ 完整 | — |
| TCP sequence prediction | ⚠️ 有限 | 内核 TCP stack |
| DoS Get | ⚠️ 有限 | WAF / Ingress |
| Slowloris | ⚠️ 有限 | Nginx L7 |
| Slow-body | ⚠️ 有限 | Nginx L7 |
| Slow-read | ⚠️ 有限 | Nginx L7 |
| Slow-range | ⚠️ 有限 | WAF |
| Bug in OpenSSL | ❌ 无法防御 | 应用层 patch / IDS |
| Credentials Hijacking | ❌ 极有限 | MFA / mTLS / SIEM / EDR |
