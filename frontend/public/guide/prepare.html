准备工作：Linux 账户、权限与 Git

读完你能：在服务器上拥有自己的 Linux 账户并获得管理权限；被邀请进 GitHub 仓库；用自己的身份提交和推送代码；（可选）把服务从原作者的个人账户迁出。
约定：<name> 代表接手人的 Linux 用户名（例如 cis），<gh-user> 代表接手人的 GitHub 用户名。原作者账户为 soar009。

P.1 为什么要用自己的账户

  • 可追溯：sudo 日志、文件修改、Git 提交都能对应到具体的人。
  • 可撤销：原作者离开后可以直接锁掉 soar009，接手人的账户不受影响。
  • 身份独立：SSH 密钥、GitHub 身份各用各的；共用 soar009 的 ~/.ssh 推送，GitHub 会认成原作者。

不要共享 soar009 的密码。

P.2 创建 Linux 账户并授权

以下命令由已有 sudo 权限的人执行（原作者，或已经是管理员的人）。如果账户已存在（例如 cis），跳过第 1 步。

# 1) 创建账户（会交互式地设置密码、全名，其余直接回车）
sudo adduser <name>

# 2) 加入管理所需的组
sudo usermod -aG sudo,docker,libvirt,kvm <name>

# 3) 确认
id <name>
# 期望看到：... groups=...(sudo),...(docker),...(libvirt),...(kvm)
组给了什么权限
sudo可以用 sudo 以 root 执行任何命令（完全管理员）
docker不加 sudo 就能 docker ps / logs / exec，管理 PostgreSQL 容器。注意：docker 组本身等同于 root 权限
libvirt用 virsh / virt-manager 管理 5 台集群虚拟机
kvm访问 /dev/kvm 硬件加速
组成员变更需要重新登录才生效（SSH 断开重连，或 newgrp docker 临时生效）。用 id 查看的是当前会话的组。

SSH 登录服务器（推荐用密钥）

# 接手人在自己的电脑上
ssh-keygen -t ed25519 -C "<name>@netsentinel"
ssh-copy-id <name>@<服务器地址>      # 输一次密码，之后免密
ssh <name>@<服务器地址>

集群访问（kubectl）

kubeconfig 是凭证，不在 Git 里。由原作者复制一份给新账户：

sudo install -d -o <name> -g <name> -m 700 /home/<name>/.kube
sudo install -o <name> -g <name> -m 600 /home/soar009/.kube/config /home/<name>/.kube/config
# 接手人验证
kubectl get nodes

P.3 过渡期：用 sudo 操作原作者的服务

服务迁移（P.4）完成前，后端和隧道仍是 soar009 的 user 级服务，接手人用自己的账户看不到也管不了 systemctl --user。这时用 sudo 切换身份：

# 进入 soar009 的环境（需要 sudo 权限，输入的是你自己的密码）
sudo -iu soar009

# 之后与原作者的操作完全一样
systemctl --user status netsentinel
systemctl --user restart netsentinel
journalctl --user -u netsentinel -f
exit                                   # 回到自己的账户
过渡办法的缺点：在 soar009 身份下做的修改和提交都记在原作者名下。不要在 sudo -iu soar009 下执行 git commit / push，代码改动请在自己账户里做（见 P.6）。

P.4 长期方案：把项目迁出个人家目录（可选，需停机）

目标：代码放到共享目录 /srv/netsentinel，用 netsentinel 组授权；服务改成系统级 systemd，不依赖任何个人账户。预计停机 15–30 分钟。

第 1 步：建组、建目录

sudo groupadd netsentinel
sudo usermod -aG netsentinel soar009
sudo usermod -aG netsentinel <name>
sudo mkdir -p /srv/netsentinel

第 2 步：停服务、搬代码

systemctl --user stop cloudflared-knettf netsentinel        # 以 soar009 执行
sudo mv /home/soar009/github/NetSentinel /srv/netsentinel/NetSentinel
sudo mv /home/soar009/knetsentinel        /srv/netsentinel/knetsentinel
sudo chown -R soar009:netsentinel /srv/netsentinel
sudo chmod -R g+rwX /srv/netsentinel
sudo find /srv/netsentinel -type d -exec chmod g+s {} +     # 新建文件自动继承组
# 让组内新建的文件默认组可写：在每个人的 ~/.bashrc 里加
umask 002

第 3 步：修复写死的路径

# 找出所有引用旧路径的地方（脚本、配置、kubeconfig 路径等）
grep -rIl --exclude-dir={.git,node_modules,.venv,dist} /home/soar009 /srv/netsentinel

# Python 虚拟环境里写死了绝对路径，搬家后必须重建
cd /srv/netsentinel/NetSentinel
rm -rf .venv
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt

# Git 会拒绝操作“别人拥有的仓库”，统一放行
sudo git config --system --add safe.directory '/srv/netsentinel/*'

第 4 步：隧道凭证移到系统目录

sudo mkdir -p /etc/cloudflared
sudo cp /home/soar009/.cloudflared/netsentinel.yml /etc/cloudflared/
sudo cp /home/soar009/.cloudflared/491d938b-3187-4d93-84da-66df739753e6.json /etc/cloudflared/   # knettf 隧道凭证（见 yml 的 credentials-file）
sudo chmod 600 /etc/cloudflared/*
# 编辑 /etc/cloudflared/netsentinel.yml，把 credentials-file 改成 /etc/cloudflared/491d938b-3187-4d93-84da-66df739753e6.json

第 5 步：写系统级服务

/etc/systemd/system/netsentinel.service：

[Unit]
Description=NetSentinel Django Backend
After=network.target docker.service

[Service]
User=soar009            # 迁移后可换成专用服务账户
Group=netsentinel
WorkingDirectory=/srv/netsentinel/NetSentinel/backend
Environment=DJANGO_SETTINGS_MODULE=backend.settings
ExecStart=/srv/netsentinel/NetSentinel/.venv/bin/uvicorn backend.asgi:application --host 0.0.0.0 --port 8080
Restart=always
RestartSec=3
TimeoutStartSec=30
TimeoutStopSec=8
KillMode=mixed
KillSignal=SIGTERM
TasksMax=500
MemoryMax=3G
MemorySwapMax=0

[Install]
WantedBy=multi-user.target

/etc/systemd/system/cloudflared-knettf.service：

[Unit]
Description=Cloudflare Tunnel (knettf.com)
After=network-online.target netsentinel.service
Wants=network-online.target netsentinel.service

[Service]
ExecStart=/usr/local/bin/cloudflared --no-autoupdate tunnel --config /etc/cloudflared/netsentinel.yml run
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target

注意：systemd 的 unit 文件里注释必须单独成行，复制时删掉行尾的 # ...。

第 6 步：切换并验证

# 关掉旧的 user 级服务（以 soar009 执行）
systemctl --user disable --now netsentinel cloudflared-knettf

# 启用系统级服务（任何 sudo 用户都能管）
sudo systemctl daemon-reload
sudo systemctl enable --now netsentinel cloudflared-knettf
sudo systemctl status netsentinel
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/api/   # 期望 200/401
journalctl -u netsentinel -f                                          # 日志命令去掉 --user
迁移后，手册其他章节里的 systemctl --user ... 都要改成 sudo systemctl ...，journalctl --user -u 改成 journalctl -u，路径 ~/github/NetSentinel 改成 /srv/netsentinel/NetSentinel。

P.5 GitHub：邀请协作者

先弄清两件事的区别：

决定什么需要邀请吗
user.name / user.email提交记录上显示的作者，只是写进 commit 的文字不需要，本地随便设
SSH 密钥 / token能不能 push 到仓库需要：密钥所属的 GitHub 账号必须是仓库协作者

所以只换邮箱不够，必须邀请接手人的 GitHub 账号（不是邮箱）。

仓库所有者（Wk-P）操作

  1. 打开 https://github.com/Wk-P/NetSentinel → Settings → 左侧 Collaborators（个人仓库叫 “Collaborators”）。
  2. 点 Add people，输入 <gh-user>，选中后发送邀请。个人仓库的协作者默认拥有读写（push）权限。
  3. 邀请 7 天内有效，过期需重发。

接手人操作

  1. 查收 GitHub 邮件，或打开 https://github.com/Wk-P/NetSentinel/invitations，点 Accept invitation。
  2. 确认自己的邮箱已在 GitHub 验证：Settings → Emails。提交邮箱要和这里的某个已验证邮箱一致（P.6 会用到）。

长期建议：转到组织

个人仓库挂在原作者账号下，原作者离开后管理不便。可以建一个 GitHub Organization（例如实验室组织），由原作者在 Settings → General → Danger Zone → Transfer ownership 转移过去。转移后旧地址会自动重定向，但建议所有人执行 git remote set-url origin git@github.com:<org>/NetSentinel.git。

P.6 本地 Git：用自己的身份提交

以下全部在接手人自己的 Linux 账户下执行（不要在 sudo -iu soar009 里）。

第 1 步：生成 SSH 密钥并添加到 GitHub

ssh-keygen -t ed25519 -C "你的GitHub邮箱"     # 一路回车，可设口令
cat ~/.ssh/id_ed25519.pub                     # 复制整行输出

GitHub → 右上角头像 → Settings → SSH and GPG keys → New SSH key，Key type 选 Authentication Key，粘贴，保存。

ssh -T git@github.com
# 期望：Hi <gh-user>! You've successfully authenticated, but GitHub does not provide shell access.
# 如果显示的是 Hi Wk-P!，说明用错了密钥

第 2 步：设置提交身份

git config --global user.name  "你的名字"
git config --global user.email "你在GitHub已验证的邮箱"
# 不想公开邮箱：用 GitHub Settings → Emails 里显示的
#   12345678+<gh-user>@users.noreply.github.com
git config --global init.defaultBranch main
git config --global pull.rebase false        # pull 时合并，与现有习惯一致
git config --global --list                   # 检查
邮箱必须和 GitHub 上的已验证邮箱一致，提交才会显示你的头像并链接到你的主页。不一致也能 push 成功，只是作者显示为灰色、不关联任何账号。

第 3 步：拿到代码

情况 A：项目已迁到 /srv/netsentinel（P.4 做过）——直接在共享目录工作：

cd /srv/netsentinel/NetSentinel
git status            # 若提示 dubious ownership，执行：
git config --global --add safe.directory /srv/netsentinel/NetSentinel
git remote -v         # 应为 git@github.com:Wk-P/NetSentinel.git

共享目录里的 .git/config 不要写 user.name/user.email（否则会覆盖每个人自己的全局设置）。检查：git config --local --list 里不应出现 user.*，有就 git config --local --unset user.name、--unset user.email。

情况 B：项目还在 /home/soar009——你没有写权限，先克隆一份到自己家目录开发：

mkdir -p ~/github && cd ~/github
git clone git@github.com:Wk-P/NetSentinel.git
cd NetSentinel

线上服务跑的仍是 /home/soar009/github/NetSentinel，改完 push 后需要 sudo -iu soar009 进去 git pull 再重启服务（pull 是拉取，不产生提交，用原作者身份执行没有问题）。

第 4 步：验证一次完整提交

git pull
git switch -c test/handover               # 建一个测试分支，不影响 main
echo "" >> README.md
git commit -am "test: handover commit"
git log -1 --format='%an <%ae>'          # 应显示你的名字和邮箱
git push -u origin test/handover          # 成功说明权限 OK
# 在 GitHub 上确认提交显示你的头像，然后删除测试分支
git switch main
git push origin --delete test/handover
git branch -D test/handover

P.7 原作者离开时的收尾清单

  1. 确认接手人能独立：自己账户 sudo 可用、kubectl get nodes 正常、测试提交 push 成功。
  2. 服务已迁到系统级（P.4），或明确约定继续用 sudo -iu soar009 管理。
  3. GitHub：仓库转到组织，或把接手人设为管理员。个人仓库无法把 Admin 授予协作者，只能转移所有权。
  4. Cloudflare：在 Cloudflare 账号里把接手人加为成员（Manage Account → Members），否则域名和隧道无人能改。
  5. 交出账号清单：网页管理员账号、数据库密码（backend/.env）、Cloudflare、GitHub。当面交接，不发聊天记录。
  6. 锁定原账户（不删除，保留文件）： 
    sudo usermod -L -e 1 soar009                 # 锁密码、设为过期
sudo gpasswd -d soar009 sudo                 # 移出 sudo 组
# 如果服务没迁移、仍是 soar009 的 user 服务，不要做这一步
  7. 从 GitHub 移除原作者的部署密钥 / 在服务器上删掉 /home/soar009/.ssh/authorized_keys 中不再需要的公钥。
