# ② 管理员在服务器上（把引号里换成收到的整行公钥）

echo 'ssh-ed25519 AAAA... cis@cis-Z10PE-D8-WS' | sudo tee -a /home/cis/.ssh/authorized_keys
sudo chown cis:cis /home/cis/.ssh/authorized_keys && sudo chmod 600 /home/cis/.ssh/authorized_keys

# ③ 接手人登录

P.2 过渡期：用 sudo 操作原作者的服务

迁移（P.3）之前，后端、隧道、crontab 都是 soar009 的，cis 直接执行 systemctl --user 看到的是自己的（空的）。用 sudo 切过去：

P.4 GitHub：邀请到两个仓库

user.email 只决定提交上显示谁，能不能 push 取决于 GitHub 账号是不是协作者。两个仓库要分别邀请：

仓库本地目录邀请页面
Wk-P/NetSentinel/home/soar009/github/NetSentinelhttps://github.com/Wk-P/NetSentinel/settings/access
Wk-P/knetsentinel/home/soar009/knetsentinelhttps://github.com/Wk-P/knetsentinel/settings/access
  1. 原作者（Wk-P）打开上面两个页面 → Add people → 输入接手人的 GitHub 用户名 → 发送。协作者自动有 push 权限，邀请 7 天内有效。

长期：两个仓库都是 Wk-P 个人仓库，原作者离开后无法给别人 Admin 权限。建议建一个实验室 Organization，用 Settings → General → Transfer ownership 把两个仓库转过去，然后在服务器上 git remote set-url origin git@github.com:组织名/NetSentinel.git（knetsentinel 同理）。

P.5 本地 Git：用自己的身份提交

第 1 步：在服务器上给 cis 配 GitHub 密钥

这是 cis 在服务器上用来连 GitHub 的密钥，和 P.1 里登录服务器的密钥不是一个。

ssh-keygen -t ed25519 -C "你的GitHub邮箱"
cat ~/.ssh/id_ed25519.pub        # 加到 GitHub → Settings → SSH and GPG keys → New SSH key
ssh -T git@github.com            # 期望 Hi 你的用户名!；若是 Hi Wk-P! 说明在用原作者的密钥

第 2 步：把两个仓库里写死的 Wk-P 身份移到 soar009 全局（必须做）

现在两个仓库的 .git/config 里都有 user.name=Wk-P / user.email=weekend2000119@gmail.com。仓库级配置优先于个人全局配置，不删的话谁提交都显示 Wk-P。soar009 本身没有全局身份，所以先补上再删：

sudo -iu soar009
git config --global user.name  Wk-P
git config --global user.email weekend2000119@gmail.com
for r in ~/github/NetSentinel ~/knetsentinel; do
  git -C $r config --local --unset user.name
  git -C $r config --local --unset user.email
done
exit

（迁移后路径换成 /srv/netsentinel/NetSentinel、/srv/netsentinel/knetsentinel。）

第 3 步：cis 的全局身份

git config --global user.name  "你的名字"
git config --global user.email "你在GitHub已验证的邮箱"   # 或 GitHub 提供的 数字+用户名@users.noreply.github.com
git config --global --list

第 4 步：在哪里改代码

已迁移到 /srv（P.3 做过）：直接在线上目录工作，改完重启服务即可。

cd /srv/netsentinel/NetSentinel && git status
cd /srv/netsentinel/knetsentinel
git remote set-url origin git@github.com:Wk-P/knetsentinel.git   # 原来是 HTTPS，改成 SSH 才能用密钥 push

还没迁移：cis 对 soar009 的目录只有读权限，只能克隆到自己家目录开发：

mkdir -p ~/github && cd ~/github
git clone git@github.com:Wk-P/NetSentinel.git
git clone git@github.com:Wk-P/knetsentinel.git ~/knetsentinel
# 改完 push 后，部署到线上：
sudo -iu soar009 git -C ~/github/NetSentinel pull     # 注意这里的 ~ 是 soar009 的
sudo -iu soar009 systemctl --user restart netsentinel

前端改动还要在线上目录 frontend/ 下 pnpm build（node/pnpm 装在 soar009 的 nvm 里，也要 sudo -iu soar009 执行）。

P.6 原作者离开时的收尾

  1. cis 能独立：sudo 可用、kubectl get nodes 5 个 Ready、两个仓库测试 push 成功。
