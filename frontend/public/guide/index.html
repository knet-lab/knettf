0.1 这个系统做什么

一句话：在一个自建的 Kubernetes 实验集群里抓网络流量，用机器学习模型判断哪些是攻击，并在网页上管理集群、扫描 Terraform 配置、查看检测结果。

它由两个独立的项目组成：

项目是什么里面主要有什么怎么运行
K knetsentinel“实验场”：搭集群、产生流量、采集数据KVM 建 5 台虚拟机的 shell 脚本；kubeadm 装 K8s；Cilium/Hubble 观测流量；Vector 把流量事件送进 Kafka；发正常 / 攻击包的 Python 脚本；数据集采集与离线评估手动执行 shell 和 Python 脚本
N NetSentinel“平台”：网页 + 后端 + 检测模型Django 后端（三个应用：kcore 集群管理、autotf Terraform 扫描、vigil 流量检测）；Vue 3 前端；OCSVM 检测模型；集群内检测器镜像一个常驻服务 netsentinel（uvicorn，端口 8080），公网经 cloudflared 映射到 https://knettf.com

网页上有三大功能，对应后端三个应用：

网页菜单前端页面后端应用做什么
Kubernetes/kcorekcore登记集群（粘贴 kubeconfig），查看 Namespace / Pod / Deployment / Service / ConfigMap / DaemonSet，看 Pod 实时日志，编辑 YAML，重启、删除
Terraform Scan/autotfautotf上传或在线编写 .tf 文件，用 terraform validate / tflint / checkov / tfsec / trivy 扫描安全问题，没有 HIGH 级问题时才允许 terraform apply
AI Vigil/vigil、/vigil/logvigil展示模型对集群流量的实时检测结果：总数、攻击数、攻击类型分布、每条流的 35 个特征和判断依据
Help/help—本手册、英文用户手册、运维对照手册
（无菜单入口）/adminkcore + autotf管理后台：用户、全部集群、全部 Terraform 配置、扫描工具

另外两条与流量无关的链路：

  • 集群管理：浏览器 → /api/kcore/... → 后端用你登记的 kubeconfig 调 Kubernetes API → 结果返回网页。Pod 日志走 WebSocket /ws/clusters/<id>/pods/<ns>/<pod>/logs/。
  • Terraform 扫描：浏览器上传 .tf → 后端存到 backend/terraform/ → 扫描时复制到临时目录，依次调用 5 个命令行工具，解析它们的 JSON / SARIF 输出 → 汇总成报告存进 SQLite。

0.4 术语表

后面各章会反复用到这些词，先过一遍，不必全记住。

KVM / libvirt / virsh
Linux 自带的虚拟化。libvirt 是管理层，virsh 是它的命令行。本项目的 VM 在 qemu:///system 下，所以命令是 virsh -c qemu:///system ...。
cloud-init
VM 第一次开机时自动执行的初始化（建用户、放 SSH 公钥、关 swap、扩容磁盘）。01 脚本为每台 VM 生成一个 cidata ISO 挂进去。
kubeadm
官方的 K8s 集群安装工具。kubeadm init 在 master 上建控制面，kubeadm join 让 worker 加入。
kubeconfig
访问 K8s 集群的“钥匙”文件，包含 API 地址（本项目 https://192.168.100.10:6443）、CA 证书和客户端证书。
Namespace / Pod / Deployment / DaemonSet / StatefulSet / Service / ConfigMap / Secret
K8s 基本对象。Pod 是运行中的容器；Deployment 管理无状态 Pod 副本；DaemonSet 每个节点跑一个；StatefulSet 给每个副本固定名字和磁盘；Service 给一组 Pod 一个稳定地址；ConfigMap / Secret 存配置和密钥。
Cilium
K8s 网络插件（CNI），用 eBPF 在内核里处理网络包。本项目让它完全替代 kube-proxy。
eBPF
在内核里运行小程序的技术，Cilium 用它看到每个网络包。
Hubble / hubble-relay
Cilium 的可观测组件。每个节点产生 flow 事件，hubble-relay（端口 4245）把全集群的事件汇总，hubble observe 命令从它读取。
Vector
日志搬运工具。本项目里它以 DaemonSet 运行，执行 hubble observe 并把输出写入 Kafka。
Kafka / topic / consumer group / offset
消息队列。消息写入 topic（本项目 ebpf-net-logs）；消费者以 group 为单位读取，各 group 互不影响；offset 是读到哪里的位置。本项目 Kafka 用 KRaft 模式：1 个 controller + 4 个 broker。
MetalLB
在没有云厂商的集群里给 type: LoadBalancer 的 Service 分配真实 IP。本项目地址池 192.168.100.200-250。
local-path
把节点本地目录当磁盘用的 StorageClass，Kafka broker 的 PVC 依赖它。
flow（流）
同一个 5 元组（源 IP、目的 IP、源端口、目的端口、协议）的一组包。模型的输入单位是“流”，不是单个包。
35 个特征
从一条流算出来的数字和字符串，例如持续时间、包数、SYN 比例、包间隔均值等，详见第 4 章。
OCSVM
One-Class SVM，只用正常数据训练的异常检测模型，偏离“正常”的样本判为攻击。
ZSL（零样本学习）
判为攻击后，拿样本和各攻击类型的“原型向量”算余弦相似度，猜它是哪种攻击；都不像就是 Unknown_Attack。
Django / DRF
Python Web 框架和它的 REST 扩展（Django REST Framework）。
ASGI / uvicorn / Channels
ASGI 是支持 WebSocket 的 Python Web 服务接口；uvicorn 是运行它的服务器；Channels 让 Django 能处理 WebSocket。
JWT（access / refresh）
登录后拿到的令牌。access 有效 2 小时，每个请求都带上；refresh 有效 7 天，用来换新的 access。
Vue 3 / Pinia / Vue Router / Element Plus / Vite
前端框架 / 状态管理 / 路由 / UI 组件库 / 构建工具。
uv / pnpm
Python 和 Node 的包管理器。
systemd user 服务
以当前用户身份运行的常驻服务，用 systemctl --user 管理，journalctl --user -u <名字> 看日志。
cloudflared
Cloudflare 隧道客户端，把本机 8080 安全地映射到公网域名。
SARIF
静态分析工具通用的 JSON 结果格式，checkov / tfsec / trivy 都输出它。

0.6 第一天就该做的 5 件事

拿到账号并登录

打开 https://knettf.com，用高级运维给你的账号登录。管理员账号登录后直接进入 /admin/dashboard。

确认能登录宿主机

SSH 到宿主机后执行下面三条，确认你有权限查看服务、数据库和集群：

systemctl --user status netsentinel --no-pager | head -5
docker ps --filter name=pg
kubectl get nodes
预期：服务 active (running)；pg 容器 Up；5 个节点 Ready（集群若没开机，看第 7 章“开机”）。
把两个仓库都打开看一眼
cd $N && git log --oneline | head -5 && ls
cd $K && ls

注意：K 的脚本和数据大多不在 Git 里，只跟踪了 README、pyproject、uv.lock、requirements.txt。改动前先备份。

看一眼实时日志
journalctl --user -u netsentinel -f

有流量时会看到 vigil.bridge: queue: N flows → M attack(s)。Ctrl+C 退出。

做一次端到端验证
cd $K && sudo .venv/bin/python3 traffic/spoof_attack.py --packets 50

然后打开网页 AI Vigil → Detection Log，15 秒内应出现源 IP 为 192.168.100.20～29 的新记录。能看到就说明整条链路是通的。

安全须知：kubeconfig、backend/backend/.env 里的 VIGIL_BRIDGE_TOKEN、数据库密码都是敏感信息，不要发到群聊或截图里。默认账号 admin / alice / bob 的密码是公开的（写在 users_init.py 里），如果还没改，第一时间修改（第 7 章）。
