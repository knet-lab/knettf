排障与日志

先用“排查顺序”定位是哪一层出了问题，再到“现象对照表”里找对应的处理办法。

排查顺序：从外到内

每一层用一条命令确认。上一层不通，就不用往下查了。

浏览器打不开 knettf.com
  ├─ curl localhost:8080 正常？ ── 否 → 后端问题：journalctl --user -u netsentinel -n 100 看启动报错
  │                                      （常见：.venv 坏了、pg 没起、.env 缺 ENVIRONMENT、settings 语法错）
  └─ 是 → 隧道问题：systemctl --user status cloudflared-knettf

网页能开，但某个功能报错
  ├─ 浏览器 F12 → Network，找失败的 /api/ 请求，看状态码和响应里的 message
  ├─ 401 → token 过期且 refresh 也过期 → 重新登录
  ├─ 403 → 不是资源的 owner，也不是管理员
  ├─ 404 → URL 拼错（末尾斜杠？）或对象不存在
  ├─ 500 → journalctl 看 Traceback
  └─ Kubernetes 页全部失败 → 集群没开机 / kubeconfig 过期

检测没有新数据
  Kafka 有数据？（健康检查第 5 步）
    ├─ 否 → 集群侧：Vector / hubble-relay（kubectl logs）
    └─ 是 → 后端日志有 bridge error？
              ├─ 是 → Kafka 恢复后重启后端
              └─ 否 → 有 drainer failed？
                        ├─ 是 → 看后面的异常，多数是缺分区
                        └─ 否 → 发包的源 IP 是不是被当成基础设施流量过滤掉了？
九成情况下，“检测没数据”的原因是 bridge 线程退出了：Kafka 出错时它会直接退出、不会重连，重启后端就好。

不要做的事

不要因为
删除 kafka-controller Pod、任何 Namespacecontroller 是裸 Pod，删了不会重建，只能重建 Kafka
同时开两条检测入口（A / B / C）各自独立消费 Kafka 并写库，同一条流会被记录两次
线上服务运行时另起 manage.py runserver会再启动一个 bridge，重复入库
sudo bash 跑集群脚本kubeconfig 会写到 root 的家目录
docker stop pg手动停过的容器开机后不会自启
在生产库上跑 users_clear / autotf_clear会清空全部用户和 Terraform 数据
Apply 不了解的 Terraform 配置会真实创建资源，而且不保留 tfstate，没法从网页 destroy
删 ~/vm-images/ubuntu-22.04-cloudimg.qcow25 台 VM 的基础镜像
