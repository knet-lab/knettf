管理员上手教程

写给第一次接手 NetSentinel 的基础管理员。全部操作在网页上完成，不需要登录服务器。界面是英文的，本文中的按钮名按界面原样写出，如 New User。
网页地址：公网 https://knettf.com，内网 http://<服务器 IP>:8080。

1. 你的职责范围

你负责（网页上能做）交给高级运维（需要登录服务器）
  • 创建、删除用户账号
  • 查看全部集群、Terraform 配置
  • 添加集群，查看和操作 K8s 资源
  • Terraform 配置的扫描、部署，扫描工具的启用 / 停用
  • 查看 AI Vigil 检测结果
  • 每日巡检，发现异常后上报
  • 改密码、把用户设为管理员
  • 服务重启、集群开关机、重建、备份恢复
  • 模型更新、代码修改
  • 网页打不开、检测数据长时间不更新

对应步骤见 运维操作逐步骤。

2. 第一次登录

打开网页

浏览器访问 https://knettf.com，会自动跳到登录页（标题 NetSentinel）。

输入账号

在 Username、Password 中填入高级运维给你的管理员账号，回车或点登录按钮。

成功：进入 Kubernetes 页面，右上角显示你的用户名。失败：出现红色错误提示，检查大小写后重试。
确认是管理员

在地址栏把路径改成 /admin，例如 https://knettf.com/admin，回车。

是管理员：进入管理后台，左侧有 Dashboard、Users、Clusters、TF Configs、TF Tools。不是管理员：被自动送回 Kubernetes 页面，请联系高级运维开通。
把管理后台加入书签

顶部导航栏没有管理后台入口，只能输入 /admin 进入。建议把 https://knettf.com/admin 加入书签。

安全提醒：系统自带的默认账号密码（admin / admin123、alice / alice123、bob / bob123）是公开的。如果你拿到的仍是默认密码，第一时间请高级运维修改。

登录状态说明

  • 登录后 7 天内无需重新登录（期间会自动续期）；超过 7 天会被送回登录页。
  • 退出：右上角 Sign Out（管理后台左下角也有）。在公共电脑上用完一定要退出。
  • 手机访问：右上角菜单按钮展开导航。

4. 用户管理

4.1 新建用户

进入 Users

管理后台左侧点 Users。

点右上角 New User

弹出 Create User 对话框。

填写
  • Username：登录名，不能和已有用户重复。
  • Email：必填，也不能重复。
  • Password：初始密码，至少 8 位、字母加数字，通过安全渠道单独告诉对方。
  • Admin 开关：保持关闭（原因见下方提示）。
点 Create
成功：右上角提示 User created，列表多出一行，Role 为 User。失败：提示 Failed to create user，通常是用户名或邮箱已存在。
Admin 开关目前不起作用：打开它新建的用户仍然是普通用户（后端忽略了这个字段）。需要新管理员时，先按上面步骤建成普通用户，再请高级运维执行 设为管理员 的命令。建好后在列表中确认 Role 变成 Admin。

4.2 删除用户

确认影响

删除用户会一并删除他名下的所有集群记录和 Terraform 配置（含扫描报告），且无法恢复。先到 Clusters、TF Configs 查看他名下有什么，必要时先通知本人。

点该行的 Delete

弹出 Delete this user?，点确认。

提示 Deleted，该行消失。
不要删除名为 vigil-bridge 的用户：它是检测系统的服务账号，删除后后台流量检测的部分功能会失效。也不要删除自己当前登录的账号。

4.3 网页上做不了的用户操作

需求怎么办
用户忘记密码 / 修改密码请高级运维重置，然后通过安全渠道告诉用户
设为管理员 / 取消管理员请高级运维处理
暂时停用某账号（不删除）请高级运维把该账号设为禁用
改用户名或邮箱请高级运维处理
登录页虽然没有注册入口，但系统接口允许任何人自行注册普通账号。巡检时注意 Users 列表中是否出现不认识的账号，发现后删除并上报。

5. 集群管理

“集群”指一个 Kubernetes 集群的访问凭证（kubeconfig）。添加后，可在 Kubernetes 页面里管理该集群。每个集群记录只属于添加它的用户。

5.1 添加集群

向高级运维索取 kubeconfig

实验集群的 kubeconfig 在服务器的 ~/.kube/config，是一段 YAML 文本。它等同于集群的最高权限密码，只能通过安全渠道传递，不要发到群聊。

打开 Kubernetes 页面

顶部导航点 Kubernetes，左侧是 My Clusters。

点 My Clusters 旁的 Add

弹出 Add Cluster。

填写并提交
  • 名称：例如 lab，同一用户下不能重名。
  • KubeConfig：粘贴完整的 kubeconfig 文本。

点 Add Cluster。

验证

点左侧新出现的集群，再点 Namespaces 标签。

能列出 default、kube-system 等即为成功。报错或一直空白：kubeconfig 不正确，或集群没有开机。

5.2 集群重建后更新凭证

集群被重建后，旧 kubeconfig 失效，页面所有操作都会报错。网页上没有编辑集群的入口，做法是删除后重新添加：

  1. 向高级运维要新的 kubeconfig。
  2. Kubernetes 页面左侧，在旧集群上点 Delete。只删除网页上的记录，不会影响真实集群。
  3. 按 5.1 用同样的名称重新添加。

5.3 查看全部集群

管理后台 Clusters 列出所有用户的集群。这里只能删除，不能进入管理；要操作某个集群，需由它的所有者在 Kubernetes 页面中进行。

6. 在 Kubernetes 页面操作资源

选中左侧集群后，右侧有 Namespaces、Pods、Deployments、Services、ConfigMaps、DaemonSets 六个标签。除 Namespaces 外，都要先在 Select Namespace 下拉框中选择命名空间。

6.1 常用查看

想知道操作怎么判断
某个服务是否在运行Pods 标签，选命名空间Status 为 Running 正常；CrashLoopBackOff、Error、Pending 需关注
为什么出错该 Pod 行点 Logs日志窗口显示 ● Connected 后实时滚动；看最后几行的 error
副本是否齐全Deployments 标签Ready 等于 Desired 为正常
服务的访问地址Services 标签Type、Cluster IP、Ports；LoadBalancer 类型显示外部地址
完整配置任意行点 YAML只读查看

实验集群中需要知道的命名空间：default（Kafka、my-nginx）、kube-system（Cilium、Hubble、Vector）、metallb-system、targets（靶机）、netsentinel（检测器，可能为空）。

6.2 重启 Deployment / DaemonSet

  1. 在 Deployments（或 DaemonSets）标签中找到目标行，点重启按钮。
  2. 选择方式：
    • Normal (Rolling)：逐个替换 Pod，服务不中断。优先用这个。
    • Force (Delete Pods)：立即删除全部 Pod 再重建，服务会短暂中断。只在 Normal 无效时使用。
  3. 点刷新按钮，几十秒后 Ready 恢复为 Desired。

6.3 编辑与新建

  • Edit：打开可编辑的 YAML，修改后点 Apply。
  • Apply YAML（右上角）：粘贴一份或多份清单（用 --- 分隔）创建资源。结果会逐条显示成功或失败。

6.4 删除

点 Delete 后弹出 Confirm Delete，提示 “This action cannot be undone.”。删除 Pod 通常会被自动重建；删除 Deployment、Service、Namespace 是永久的。

实验集群中以下对象不要在网页上删除或强制重启，否则整套检测链路中断，需要高级运维重建：
  • default 命名空间中的 kafka-controller（删除后不会自动重建）、kafka-broker-*
  • kube-system 中的 cilium、hubble-relay、vector
  • metallb-system 中的任何对象
  • 任何 Namespace

7. Terraform 扫描与部署

7.1 创建配置

进入 Terraform Scan，点 My Configs 旁的 New

弹出 New Terraform Config。

二选一
  • Upload File：填 Name，选择本地 .tf 文件。
  • Write Online：填 Name，在 Content 中粘贴或编写配置。
点 Create
左侧列表出现该配置。名称重复会创建失败。

7.2 扫描

  1. 左侧选中配置，右侧 Config Content 显示内容，可点 Edit 修改后保存。
  2. Security Scan 区域：
    • Full Scan：用所有已启用的工具扫描。
    • 手动扫描：弹出 Manual Scan — Select Tools，只勾选需要的工具。
  3. 扫描需要几秒到一分钟，期间按钮转圈，不要刷新页面。
  4. 完成后 Scan Report 显示 HIGH / MEDIUM / LOW / TOTAL 数量，以及每个工具的问题列表（规则、严重级别、描述、位置）。全部通过时显示 ✓ Clean。
  5. View Report 在新窗口打开 HTML 报告；Download PDF 下载 PDF。
某个工具的结果显示 tool not found，表示服务器上缺少这个工具，其他工具的结果仍有效。请上报高级运维，或先在 TF Tools 中停用它。

7.3 部署（Terraform Apply）

Deploy (Terraform Apply) 区域的 Apply 按钮只有满足下列全部条件时才可点击；灰色时把鼠标停在按钮上可看到原因：

提示含义处理
Run a scan first还没扫描过先 Full Scan
Scan must be complete扫描未完成或失败重新扫描
Fix all HIGH severity issues first存在高危问题修改配置，消除全部 HIGH 后重新扫描
Apply 会真实创建配置中的云资源，可能产生费用。系统不保留 Terraform 状态文件：同一配置重复 Apply 会再次创建，也无法从网页销毁已创建的资源。点之前务必确认内容。

结果在页面上显示为成功或失败，附带完整输出；失败时把输出发给配置作者。

7.4 管理扫描工具（TF Tools）

操作步骤
临时停用某个工具该行 Edit → 关闭 Enabled → Save。Status 变为 Disabled，Full Scan 不再使用它
重新启用同上，打开 Enabled
删除工具Delete → 确认。建议用停用代替删除，删除后需高级运维才能恢复
新增工具需要填写命令和输出解析字段，请交给高级运维，不要自行尝试

当前工具：terraform_validate、tflint、checkov、tfsec、trivy，正常情况下应全部为 Enabled。

8. 查看流量检测（AI Vigil）

8.1 看板 /vigil

区域含义
顶部 LIVE、Last updated页面每 30 秒自动刷新；Refresh now 立即刷新
Detection model当前使用的检测模型（正常为 ads_ml_ocsvm）。显示 No models registered 说明模型没加载，需上报
Total Inspected / Attacks Detected / Normal Flows / Attack Rate累计检测的流数、其中判为攻击的数量、正常数量、攻击比例
Attack Type Breakdown各攻击类型的数量
Model Coverage各模型检测的数量
Recent Attack Events最近的攻击记录；View log → 进入完整日志

8.2 检测日志 /vigil/log

  1. 顶部筛选：结果（全部 / 攻击 / 正常）、攻击类型（All types 或具体类型）、时间范围（Clear time 清除）。
  2. 每页条数可选 50 / 100 / 200 / 500，用 ← Prev、Next → 翻页；页面每 15 秒自动刷新。
  3. 点任意一行查看详情：
    • Flow：源、目的、协议
    • Ground Truth：实验时的真实标签（只有实验流量才有）
    • Detection Result：是否攻击、置信度、攻击类型、说明
    • ZSL Similarity Ranking：与各攻击类型的相似度排名
    • Cilium Response：系统建议的处置动作
    • Flow Features：送入模型的全部特征

8.3 结果怎么读

字段说明
Verdict攻击或正常
Confidence与最相似攻击类型的相似度（0~1），越高越像该类攻击；正常流量为 0
Attack Type9 类之一（如 Dos-TCP SYN flood、Slowloris、DoS Get）；Unknown_Attack 表示异常但不像任何已知类型
Cilium actionignore 不处理 / alert 告警。目前只是建议，系统不会自动封禁
Label / Ground Truth1 = 实验中的攻击流量，0 = 实验中的正常流量，空 = 非实验流量

来源 IP 为 192.168.100.20~29、170~184 的通常是实验发出的模拟攻击，属于预期内的“攻击”。

10. 遇到问题时

10.1 自查

现象先试
页面白屏或按钮没反应Ctrl+F5 强制刷新；换浏览器或无痕窗口
突然被送回登录页重新登录（超过 7 天会过期）
操作提示 Forbidden该对象不属于你，或你不是管理员
Kubernetes 页面全部报错集群可能关机或被重建 → 上报；重建后按 5.2 更新
Logs 窗口显示 ○ Disconnected关闭后重新打开；Pod 已重启时选新的 Pod
扫描一直转圈超过 3 分钟刷新页面查看报告状态，失败则重新扫描

【位置】https://knettf.com/vigil/log
【已做】刷新页面、重新登录，问题依旧

11. 禁止事项

  • 不要在群聊、邮件、截图中泄露 kubeconfig、密码或 token。
  • 不要删除 vigil-bridge 账号和自己的账号。
  • 不要在实验集群中删除或强制重启 Kafka、Cilium、Hubble、Vector、MetalLB 以及任何 Namespace。
  • 不要对不了解内容的 Terraform 配置执行 Apply。
  • 不要删除扫描工具，改用停用。
  • 不要在公共电脑上保持登录。
