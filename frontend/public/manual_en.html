📋 Overview

Platform Overview

NetSentinel is an all-in-one platform for DevOps and security teams. It provides real-time Kubernetes cluster monitoring, Terraform configuration security scanning, and one-click deployment capabilities.

☸️ Kubernetes Monitoring
  • Connect and manage multiple K8s clusters
  • Browse Namespaces, Pods, and Deployments
  • Inspect Services and ConfigMaps
  • Stream live Pod logs in real time
🔍 Terraform Security Scan
  • Upload or write .tf configs online
  • Multi-tool security scanning pipeline
  • HIGH / MEDIUM / LOW severity classification
  • One-click Terraform Apply after a clean scan

🔐 Authentication

Login & Authentication

Open the Login Page
Navigate to http://localhost:5173/login and enter your username and password.
Automatic Token Management
After a successful login the platform obtains an Access Token (valid for 2 hours). When it expires, the token is silently refreshed in the background — no manual re-login needed until the Refresh Token (7 days) expires.
Sign Out
Click the Sign Out button next to your username in the top-right corner to end your session.
ℹ️
Admin accounts can access the /admin path to enter the admin console. Standard users are redirected away from this path.

🚀 Terraform Apply

Deploy — Terraform Apply

Once all prerequisites are met, you can execute terraform apply directly from the platform to deploy the configuration to the target cluster.

Prerequisites for Apply (all required)

🚫
Both conditions must be satisfied before the Apply button becomes clickable:
① Scan completed (status shows Scanned)
② Zero HIGH-severity findings in the scan report

Execution Steps

Confirm the Scan Passed
Check the Risk Summary in the Scan Report and confirm HIGH 0.
Click the Green Apply Button
When prerequisites are met the Apply button in the Deploy card turns green and becomes clickable.
Wait for Completion
The platform runs terraform init followed by terraform apply -auto-approve. Results are displayed when finished.
Review the Output
After Apply completes, the full terminal output is shown below the card with a success or failed status and execution time.
⚠️
The .tf file must contain valid cluster connection information (API endpoint, credentials). Otherwise terraform init will fail at the first stage.

🤖 AI Vigil

AI Vigil

AI Vigil provides real-time network anomaly detection powered by machine learning. It continuously monitors all traffic flowing through the Kubernetes cluster via Cilium / Hubble eBPF, classifies each flow, and pushes results to the dashboard over WebSocket.

Detection Pipeline

1
Traffic Capture — Cilium / Hubble eBPF
Hubble hooks into the Cilium dataplane at the eBPF level and exports every network flow (TCP, UDP, ICMP) as a structured JSON event to a Kafka topic (ebpf-net-logs). No agents need to be installed on workloads.
2
Flow Aggregation — Bridge
The backend bridge thread consumes Kafka events and aggregates raw packets into per-flow feature vectors (30 statistical features: packet counts, IAT statistics, TCP flag ratios, directionality, etc.). Aggregation is triggered every 100 packets or every 2 seconds, whichever comes first. Infrastructure-internal flows are filtered out automatically.
3
Anomaly Detection — OCSVM + ZSL
Each aggregated flow is scored by a One-Class SVM (OCSVM) pipeline. Flows scoring below the anomaly threshold are flagged as attacks. A Zero-Shot Learning (ZSL) cosine-similarity step then maps the flow embedding to the nearest known attack-type prototype (e.g. Slowloris, SYN Flood, Credential Hijacking) to produce a human-readable classification and confidence score.
4
Real-time Push — WebSocket
Detection results are saved to the database and immediately broadcast to all connected frontend clients over WebSocket (/ws/vigil/). The sidebar status pill turns green (WS) when a live connection is established. If the connection drops, the dashboard falls back to polling every 10 seconds and attempts to reconnect automatically.
5
Cilium Response
Based on the detection result, a Cilium policy action is suggested and logged: alert (log only), rate_limit (throttle the source), or drop (block the flow). Actions are visible on each detection record.

Detection Record Detail

Click any row in the Detection Log to open its detail panel, which shows:

  • Flow — source / destination IP and port, protocol, timestamp, and ground-truth label (if available from simulation).
  • Detection Result — model name, confidence score, classified attack type, and explanation string.
  • ZSL Similarity Ranking — ranked similarity scores against all known attack-type prototypes, visualised as a bar chart.
  • Cilium Response — the policy action taken and the reason string.
  • Flow Features (30) — raw feature vector used for inference, including duration, packet counts, IAT statistics, and TCP flag ratios.

⚠️ Appendix

Severity Levels

LevelMeaningEffect on Apply
HIGH Critical security issue — clear vulnerability or dangerous misconfiguration Blocks Apply — must be fixed and re-scanned
MEDIUM Moderate risk — remediation recommended but not mandatory Does not block Apply
LOW Low-risk informational finding — best-practice suggestion Does not block Apply

Scan Tool Reference

📦 terraform validate

Official Terraform validation command. Checks HCL syntax correctness and resource reference validity. Outputs JSON with error/warning levels.

📦 tflint

Terraform Linter. Detects deprecated resources, variable type errors, and Provider best-practice violations. Outputs JSON.

📦 tfsec

Focused on security configuration scanning. Detects overly permissive IAM roles, publicly exposed ports, plaintext secrets, and more. Outputs SARIF.

📦 checkov

Compliance scanning tool with 500+ built-in rules. Supports Terraform Kubernetes Provider resources and CIS Benchmark checks (CKV_K8S_* rule family). Outputs SARIF.

📦 trivy

Comprehensive scanner by Aqua Security. Covers IaC misconfigurations and known CVE vulnerabilities. Outputs SARIF.
